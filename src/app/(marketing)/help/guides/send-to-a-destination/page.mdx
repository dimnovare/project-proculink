import { guideMetadata } from "@/lib/seo";

export const metadata = guideMetadata({
  slug: "send-to-a-destination",
  title: "Send outputs to a destination — ProcuLink guide",
  description: "Send a flow's output by email, to a web address, to an SFTP or FTPS server, or as a download.",
});

import { Step, Prereqs, IfThisFails, Outcome } from "@/components/help/guide";

<Prereqs>
- A flow with an output, or one you are about to make. See [Build an output](/help/guides/build-an-output).
- A workspace admin account.
- The details of the place the file goes: for email, the addresses. For a web address, the URL and how it wants you to sign in. For SFTP or FTPS, the server, port, folder, user name, and password or key.
</Prereqs>

<Step n={1} title="Open the destination form">

Open the output's form: on the flow's **Outputs** tab, select **Add an output**, or **Edit** on an existing output. In the **Send to** list, choose **New destination…**.

<Outcome>
The **New destination** form opens under the list.
</Outcome>

</Step>

<Step n={2} title="Name it and choose how it is sent">

Type a **Name** that tells you where the file goes. Choose **Send by**:

- **Web address (API).** Fill in the **Web address** (it must start with `https://`) and the **Request method**, POST or PUT. **Give up after (seconds)** starts at 30.
- **SFTP** or **FTPS.** Fill in the **Server**, the **Port** (22 for SFTP, 21 for FTPS) and the **Folder on the server**. Two boxes are ticked to start with: **Create the folder if it is missing** and **Replace a file with the same name**. FTPS also has **Accept an untrusted certificate**, which is off.
- **Email.** Fill in **Send to** with one or more addresses, separated by commas. Add a **Reply-to address** if you want one. ProcuLink writes the subject and the message itself: the subject shows the flow name and the file name, and the message says the file is attached.

<Outcome>
The form shows the boxes for the way you chose.
</Outcome>

</Step>

<Step n={3} title="Add the sign-in">

Fill in the sign-in the place asks for. A web address can use a bearer token, an API key or a user name and password. SFTP and FTPS use a user name with a password, and SFTP can use a private key instead. Email needs none. See [Destination sign-in, keys and signing](/help/destination-sign-in).

<Outcome>
The login is filled in. After you save it, it is encrypted and never shown again.
</Outcome>

</Step>

<Step n={4} title="Save it">

Select **Save**. The form closes and the new destination is chosen in **Send to**. Passwords and keys are encrypted as they are saved.

<Outcome>
The destination exists and is ready to use in the output.
</Outcome>

<IfThisFails>
If the form refuses to save, the message says why. A web address that does not start with `https://`, or one with a user name and password written into it, is refused. If a login is only half filled in, fill in all of it or none of it.
</IfThisFails>

</Step>

<Step n={5} title="Use it in an output and test it">

Back in the output form, the new destination is already chosen in **Send to**. Select **Create** or **Save**. Any other output in your workspace can use the same destination.

If the flow has been published, publish again so new sends use the change. See [Publish and restore flow versions](/help/guides/publish-a-flow-version).

A test is offered in two places. The new-flow guide shows **Send a test** right after you save a destination, and an output built from documentation will not be created until a test has passed. A test sends a small file named `TEST_proculink-test.txt` that says it is a test and holds no document data. An email subject starts with `[TEST]`, and a web request carries an `X-ProcuLink-Test` header. On SFTP and FTPS the test file stays in the folder, so delete it when you are done.

Anywhere else there is no separate test, so the first real send is the test. Start with one document you are happy to send.

<Outcome>
The output is tied to the destination.
</Outcome>

</Step>

<Step n={6} title="Send a document and watch it">

Open a document that is ready and select **Send** on the **Outputs** pane. Below the outputs, **Deliveries** lists each one with its way of sending, its state and how many attempts it took.

- **Waiting** and **Sending** are in progress.
- **Delivered** means the destination accepted the file.
- **Will retry** shows the reason the last try failed. We try again after about 30 minutes, and once more about an hour later.
- **Couldn't deliver** is the end of the three attempts. The document shows **Couldn't send**.

<Outcome>
Every delivery is **Delivered** and the document is **Sent**.
</Outcome>

<IfThisFails>
Read the message beside the delivery. A failed sign-in, a wrong port, a folder that is missing and cannot be created, or a web address that answers with an error are the usual causes. Fix the cause, then press **Send** on the document again. Deliveries that already worked are not sent twice. See [Destinations](/help/destinations) for how retries work, and [Troubleshooting](/help/troubleshooting).
</IfThisFails>

</Step>
