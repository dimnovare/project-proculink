<Prereqs>
- A ProcuLink workspace you can sign in to. Nothing in this guide sends anything to your supplier, so it
  needs no delivery set-up: adding a supplier, uploading, reviewing and downloading work the same on every
  plan, Pilot included.
- **One order you would really send to that supplier** — a real one, a test copy, or one with the customer
  details blanked out. A made-up sample proves the plumbing and teaches you nothing about your own
  documents.
- A supplier you order from again and again, so that step 6 has a second order to show you.
- A laptop or desktop screen for steps 4 and 5. On a phone the review screen lets you check and send, but
  the preview has no **Download** button.
</Prereqs>

<Step n={1} title="Add one repeat supplier">

Item codes are saved per supplier, and every order is checked against one — so start with a single supplier
you order from often.

Open **Suppliers**, press **New supplier**, type the name, and press **Add supplier**. A name is enough.

The same panel offers a delivery channel and an output format. Leave both empty for now: delivery is the
last thing you need, not the first, and this guide never uses it.

The supplier's identifiers (the **Identifiers** card on its **Overview** tab) and their price list (the
**Catalog** tab) both make later orders smoother, and neither is needed today. When you want them: [add a
supplier and fill in their identifiers](/help/guides/add-a-supplier) and [import a supplier catalog from a
file](/help/guides/import-a-supplier-catalog).

<Outcome>
The supplier appears in **Suppliers**.
</Outcome>

</Step>

<Step n={2} title="Upload a real, test or anonymised order">

Press **Upload order** in the top bar. Under **Send to**, choose the supplier you just added — this only
says who the order is for; nothing is sent. Add the file and press **↑ Upload & review**.

CSV, XLSX, and text-based PDF are the everyday formats; structured XML, cXML, UBL, EDIFACT, X12, and SAP
IDoc are read too. Each file becomes its own order — files are never merged.

ProcuLink reads the file in the background and opens the review screen when it is ready. More on the upload
screen itself: [upload order files by hand](/help/guides/upload-orders-manually).

<Outcome>
The order opens on its own review screen, with the right purchase-order number and its line items.
</Outcome>

<IfThisFails>
An order that stops at **Couldn't read file** is a document problem rather than a ProcuLink one — most
often a missing required column, a scanned PDF with no text layer, or an encoding that mangled the header
row. See [troubleshooting common parse errors](/help/troubleshooting).
</IfThisFails>

</Step>

<Step n={3} title="Confirm the supplier item codes that need attention">

The review screen has three columns: **What we received** on the left — your original document, which stays
in view the whole time — **What we'll send** in the middle, and on the right **Issues** stacked above the
**Live preview**.

The issues are listed under **Before you send**. Most on a first order are item codes: your code is known,
the supplier's code for the same product is not. For each one:

- **Accept suggestion** when the suggested supplier code is right. A match percentage appears beside it only
  when the suggestion was scored.
- **Enter manually** when it is not, and type the supplier's own code.

Only entries marked **Blocker** stop the order; a **Warning** is worth a look but holds nothing up. Check
each suggestion rather than accepting them all at once — on a first order, this is where you learn how the
supplier's codes line up with yours.

Every code you confirm is saved for this supplier as a pair — your code and theirs — and used again on the
next order from them. The saved pairs are listed under **Suppliers → the supplier → Item codes**. More:
[resolve item codes in review](/help/guides/resolve-item-codes).

<Outcome>
The panel reads **Ready to send · No open issues. This is everything ProcuLink can check before sending — it
is not a guarantee that the supplier will accept the order.**
</Outcome>

<IfThisFails>
If most lines need a code typed by hand, the supplier's price list is missing. Importing it on the
**Catalog** tab gives suggestions something real to match against — see [import a supplier catalog from a
file](/help/guides/import-a-supplier-catalog).
</IfThisFails>

</Step>

<Step n={4} title="Review the supplier-ready result">

The **Live preview** on the right is the document ProcuLink has built for this supplier from the order you
just checked. If that column is folded into a narrow **Preview** strip, click the strip to open it.

Read it against **What we received** on the left: the purchase-order number, the item codes — theirs now,
not yours — the quantities and units, and the total. The **Generated** tag above it means ProcuLink built
the document from the order; it has not been checked against a standard.

If the shape is wrong rather than the values — a field the supplier needs is missing, or named differently
— that is a layout job, not a review job: [map a supplier's purchase-order
fields](/help/guides/map-supplier-po-fields).

<IfThisFails>
If the preview says the order *still needs review* instead of showing a document, an item code from step 3
is still open. Clear it and the preview fills in.
</IfThisFails>

</Step>

<Step n={5} title="Download it and send it yourself">

Use the format buttons above the preview to pick the format the supplier reads — the preview switches with
them. Then press **Download**, the small button at the right end of that row, beside **Copy**.

It saves the document exactly as previewed, named after its format — `preview.csv`, `preview.xml` and so on.
Rename it to something the supplier will recognise, then send it the way you send orders today: attach it
to an email, or upload it to their portal.

ProcuLink produces structured files such as CSV, JSON, XML, UBL 2.1 and X12 850. It does not produce PDF or
Excel files; a CSV opens in any spreadsheet program.

Downloading changes nothing in ProcuLink. The order is not marked as sent — ProcuLink only marks an order
**Delivered** when it sent it itself — so it stays **Ready to send** in your queue. Do not press **Send to
supplier** on it: with no delivery set up, the confirmation tells you that send will fail.

<Outcome>
The supplier has a correct order from you, in a format their system reads, and you checked every line of it
before it left.
</Outcome>

</Step>

<Step n={6} title="Run the next order from the same supplier">

The first order proves ProcuLink can read your documents. The second shows what it remembers.

When the next order for this supplier comes up, upload it exactly as in step 2. Lines whose codes you
confirmed in step 3 arrive with the supplier's code already filled in, so **Before you send** lists only
products you have not ordered through ProcuLink before.

<Outcome>
The second order needed less work than the first, and every order after it needs less again.
</Outcome>

<IfThisFails>
If the list is as long as last time, the codes on the two documents are not identical — a stray prefix, a
trailing space, or a different code column in your export. Compare one line from each order.
</IfThisFails>

Once a few orders like this have come out right, [ready to automate delivery?](/help/guides/automate-delivery)
covers letting ProcuLink send them to the supplier for you — and, later, letting orders arrive without an
upload.

</Step>
