# Files we make

The formats a flow can produce, and how each field gets its value.

A file we make is what your receiving system gets. A flow can make several files. Each one has a format, a list of values, and a place it goes: a destination, or **Download only**. Every plan has every format. Only a workspace admin can add or change files.

## The formats

- **CSV.** Rows and columns. You choose the separator: comma, semicolon or tab.
- **Excel.** The same rows and columns in an .xlsx file.
- **JSON** and **XML**. The values sit under names you choose.
- **PDF.** A page people can read. You can add a title, text at the top, text at the bottom, and a logo (PNG or JPG, up to 256 KB).
- **Text.** A plain text file, with the same title and text options as PDF.
- **Fixed-width text.** Every value gets a set width in characters, from 1 to 1000. The default is at least 40.

## Where each value comes from

Each row of a file has a column name and a source. The source is one of three things:

- **A field of the document.** For example, the document number or a date.
- **A fixed value.** One that you type, the same on every document.
- **A field swapped through a lookup.** The value on the document is replaced by the one your system uses. See [Lookups](/help/lookups).

If the flow has a table, you can pick it, and its columns become the columns or rows of the file.

## Send only some documents

A file can be set to **Always** send, or **Only when** a field matches a condition. Use this to send one file per recipient. If a document matches no file, nothing is sent and the document waits for you.

## Preview before you rely on it

On the flow's **We send** step, **What the file looks like** shows the file made from the latest document, with your changes.

## When changes take effect

Before the first save of the setup, changes to files are in use straight away. After that, a document is sent with the setup in use, so a change to a file reaches new sends once you use your changes. See [Use changes and restore earlier versions](/help/guides/publish-a-flow-version).

## Ways to make a file

- [Make a CSV of every value we read](/help/guides/build-an-output), then untick what you don't need. This is how **Make a second file** opens: it adds a file, so each document then gives two.
- [Match a sample file](/help/guides/build-an-output-from-a-sample) of what your system expects.
- [Start from your system's documentation](/help/guides/build-an-output-from-documentation), and we propose the file for you to check.
- Choose **A standard format** when your receiver asked for one: cXML, UBL, EDIFACT or X12 for orders, and ZUGFeRD / Factur-X for invoices. The ones that fit your documents come first; the rest are one press further down, where they apply. A ZUGFeRD or Factur-X invoice's readable page is in the invoice's language (German, French, Polish or Estonian from the seller's country, otherwise English); the data inside it is the same in every language. See [Send e-invoices](/help/guides/send-e-invoices).

**Change the file** replaces the file a flow makes instead of adding one: press **Change** next to **File type** on the file's card, or **Change the file** on a document. Pick a common type, a sample, documentation or a standard. You see the new file first. **Use this file** puts it in place and keeps where it goes; **Cancel** changes nothing.

Then choose where it goes. See [Destinations](/help/destinations).
