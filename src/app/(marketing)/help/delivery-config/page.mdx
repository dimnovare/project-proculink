# Configuring supplier delivery

Delivery is the last stage of the pipeline — a transformed order has to actually land at the supplier. Configure one delivery destination per supplier under **Library → Suppliers → Delivery**.

## Choosing a protocol

ProcuLink supports these delivery channels:

- `HTTP webhook` — the default. Works with any supplier that exposes a JSON/XML endpoint. Auth: none, API key, bearer, basic, or OAuth2 fetch-token.
- `SFTP` / `FTPS` — drop the order file on the supplier's server (password or private key).
- `Email (SMTP)` — send the order as an email attachment.
- `Erply` / `Directo` — purpose-built adapters for those ERP tenants (authentication + field mapping handled for you).

Pick HTTP when the supplier publishes an API, SFTP/FTPS or email for file-based suppliers, or the ERP adapter when you share an Erply/Directo tenant. The output format each supplier receives is set on the same Delivery tab.

## Configuring HTTP delivery

Enter the webhook URL, the auth method (`none`, `API key`, `bearer`, `basic`, or `OAuth2 fetch-token` — which fetches a fresh access token from the supplier's token endpoint before each send), and any required headers. Credentials are encrypted at rest with AES-256-GCM.

## Test-fire before going live

Click **Send test payload**. ProcuLink posts a sample order so you can confirm the supplier's endpoint accepts the format and returns a 2xx. Production traffic is paused on the supplier until at least one test-fire succeeds.

## Delivery status meanings

An order moves `ready_to_deliver` → `delivering` → `delivered` on success. On failure it lands in `delivery_failed` with the response body captured for retry. A transform artifact alone does not mean the order was sent — the explicit `delivered` state is the source of truth.
