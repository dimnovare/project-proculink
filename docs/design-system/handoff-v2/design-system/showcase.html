Signature components

Three of the five signatures this section was written around make a ProcuLink screen recognizable. Two — edge rails and the canonical spine — were struck on 2026-08-13 and are marked below. See CLAUDE.md §2 for the current built/not-built table, and 05-components.md for specs of what remains.

Edge rails (left = buyer · right = supplier)

Struck · 2026-08-13

Never built. A live demo of edge rails used to render in this slot. The <EdgeRails> component was never written into the app, and every token and class created for it — .railed, .rail, .rail-port, .rail-label, the rail: 4px spacing token, the z-rails z-index, and the bg-rail-buyer / bg-rail-supplier background images — carried zero consumers for its entire life. All of it was deleted with the signature. The demo was removed because a rendered demo argues for a thing far more persuasively than prose does, and this one was arguing for something that did not exist.

What carries buyer-left / supplier-right instead: panel order on the review screen — the source document pane ("What we received", blue) stays left of the outgoing panes ("What we'll send" and the live preview, green), and that ordering is the orientation — plus a labelled Buyer → Supplier direction column in the order queue. Colour semantics are unchanged: buyer / incoming #1E66C9, supplier / outgoing #2E8E3A.

One gradient survived the strike under a new name: --gradient-rail-buyer is now --gradient-line-buyer, because a real consumer draws with it — the vertical connector through a help guide's numbered step badges. It is a step connector, not a rail. --gradient-rail-supplier was deleted outright.

Do not reinstate the rails as decoration. They were struck because a 4px strip at the window edge is not how anyone reads direction.

Wire topology (the "System map" tab on the dashboard)

Demoted 2026-08-13. Wire topology ships and is unchanged visually, but it is no longer the dashboard centerpiece this page called it — it now lives behind a "System map" tab on /bridge, not as the hero of the landing screen.

Canonical spine review (3-column source · spine · output)

Struck · 2026-08-13

Deleted. A live demo of the canonical spine used to render in this slot. CanonicalSpine.tsx (<CanonicalSpine> + <SpineNode>) had zero importers and was deleted from the app, along with its spine: 3px spacing token, whose only consumer was that file. The reference implementation under components/ went with it, and the CSS that styled this demo was removed from this page.

What ships instead: a three-pane workbench on the order review screen — source document ("What we received") on the left, the outgoing payload ("What we'll send") in the middle, and a live preview of exactly what the supplier receives on the right. It is a different and better shape than source · spine · output: the middle column is the editable field mapping, not a read-only canonical spine, and the right column previews the real outgoing payload rather than a static sample.

The one rule from this spec that survives, because it is true and load-bearing: the source document stays visible on the left during review. Never hide the source behind a modal or a wizard step.

Note the naming collision — the link-spine (the 2px blue→green gradient across the bottom of the topbar, bg-link-spine / --gradient-link-spine, demonstrated in the Motion section below) is a different thing and still ships. Only the canonical spine was struck.

Download & handoff

The complete system is a folder of Markdown, tokens, components, and SVG assets. Drop the folder into your repo and point Claude Code at the included brief.

For Claude Code

  1. Drop the design-system/ folder into your repo.
  2. Hand Claude Code the file 10-claude-code-brief.md.
  3. Wire tokens/tailwind.config.ts into your Tailwind config.
  4. Import the signature components from components/.

For a designer (Figma)

  1. Import tokens/tokens.json with the Tokens Studio plugin.
  2. Use this showcase as the visual reference.
  3. The mark family lives in assets/logo/.
